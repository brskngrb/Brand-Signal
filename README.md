# Bakery Clearly 第二代

雙擊 `start.bat` 開啟工作區，或用 `start-with-logs.bat` 查看啟動紀錄。專案包含 Node、Python、Ollama 及已下載的 `qwen3.6:35b` 模型。

## 原型搜尋觀測

1. 將 `.env.example` 複製為 `.env`，在 `TAVILY_API_KEY` 填入自己的金鑰後重啟。
2. 在「品牌觀測」的「原型批次搜尋觀測」選單執行單題或整批 20 題。每題由 Ollama 準備搜尋詞，Tavily 回傳最多五筆結果，再由程式計算品牌出現位置並由 Ollama 分析相關性。
3. 成功的題目即寫入 `data/brand_observations.db`。原型的歷史紀錄保存在 `data/prototype-observations.sqlite`，可在同一頁查看。搜尋結果位置依該次 Tavily 回傳順序計算。
4. 原有 AI 回答觀測、商品與圖片分析、內容健檢、助理及待辦仍可從網頁操作。使用舊系統瀏覽器內的觀測紀錄時，請先從舊系統匯出。

命令列可執行 `.runtime\python\python.exe -X utf8 agent.py --search`。命令列從環境變數讀取 `TAVILY_API_KEY`。加上 `--query-index 1` 可只跑第一題。

## 內容改善與外部驗證

首頁「內容改善與驗證」串起三步：

1. **問題—證據—缺口**：80 題對照已收集官網的欄位與摘錄，可按情境、題型與狀態篩選。自動命中只是線索；人工判定需核對人、來源與說明，來源更新後提示重核。
2. **可上稿修改包**：由題目或首頁建議建立，包含目標官網、區塊、原文快照、新文、待確認欄位及驗收方式。可編輯或由已連線模型寫稿，下載 Markdown 交品牌上稿。核准需填核對人及完成待補；模型重寫取消原核准。
3. **發布與前後測**：先保存改善／對照題目、對照官網頁與固定條件，記錄基準。品牌完成官網上稿後再記錄實際發布日與內容版本，鎖定稿件快照。可重新讀取發布頁，核對原文擷取情況。

每平台、模型各保存改善／對照兩組前後回答。測試入口會帶入固定題目與條件；只比較搜尋開啟、全新對話、版本與條件相同的人工回答，發布同日不比較。每個指標只採四格都有唯一、同輪次且已查核的樣本；重複、缺值、API／本地樣本及不符條件資料不混算。呈現分子／分母與兩組變化差，屬描述性結果，不宣稱因果。

改善資料依品牌保存在目前瀏覽器的 `signal.content-workflow`。可匯出修改包及完整改善／實驗 JSON，一般報告也附此資料；一般匯入目前不自動還原改善流程。外部回答仍需人工取得及核對，並非自動操作外部平台。

## 五項 MVP 與首頁操作

1. **蒐集資料**：首頁「收集／更新官網資料」快速取得鴻鼎菓子官網樣本（每次最多 6 頁）；主題探索預設目標 100 個不同公開頁面。時間、來源限制或連續六批無新頁面會提前停止並顯示差額，不把目標當作已取得數量。
2. **品牌知識**：五類收合資料列保留來源原文、網址、讀取日期與人工核對狀態。內容改變會要求重新核對；目前是來源線索表，非完整商品目錄。
3. **固定題庫**：「AI 題庫與紀錄」提供指定／未指定品牌各 40 題，涵蓋送禮、採購、成分與預算。
4. **觀測紀錄**：保存回答原文及提及、推薦、官網引用的「是／否／待查核」。各指標只使用已查核分母；人工平台觀測與 API 採樣分開。
5. **具體改善**：首頁直接呈現最多三張修改卡，寫明頁面／區塊、要補的欄位或 FAQ 草稿。依據與驗證方式可展開；缺少可核對證據的模型回答不取代有資料支持的規則方向。

主題探索每批最多 6 頁、全程最多 60 批／200 頁／20 分鐘。100 頁為收集目標；模型接收整體統計與最多 6 頁摘錄，不代表逐頁全文閱讀。瀏覽器保留最近 100 頁，SQLite 保存全部成功寫入來源。價格、成分與服務條件未確認時只提供「待補」草稿。

從公開網站收集資料，保存至本地 SQLite，再以關鍵字與頁面關係支持 Agent 建議。介面分為「首頁」、「關鍵字與 Agent」及「API 與模型」三個分頁，預設使用本機 **Qwen3.5 4B**（`qwen3.5:4b`）。品牌範例沿用鴻鼎菓子的送禮與採購情境。

### 首頁與建議操作

首次使用只需輸入主題，頁數、時間與指定網址收在「搜尋設定」。有資料後，首頁優先顯示資料概況與 Agent 建議；按「再次探索」即可展開保留的搜尋設定。收集期間顯示進度，完成後自動收起表單並回到成果。

搜尋入口上方集中顯示搜尋、模型、儲存三項狀態，附對應的設定、測試及重試入口。雲端模型只提供金鑰時顯示待驗證，成功回應後才標為已連線。本地未啟用時仍可進行主題搜尋，停用本地 Qwen 規劃選項。首頁的雲端「測試模型」會發送一則簡短測試請求，依供應商正常計費；本地測試只確認服務與所選模型。

Agent 分析整理成最多三張建議卡，各自包含資料依據、建議動作、驗證方式及可展開的保存原文。模型引用只對應本次實際提供的來源，數字須與工作區計算結果完全一致；未對應的證據會標為待核對。每張卡可個別追問或加入待辦，同一份分析的同一張卡不會重複加入。舊格式或無法解析的分析保留在「模型原始分析」，主畫面改用明確標示的內容比對卡。

## 計畫書對應的第一階段 MVP

本輪依第一版計畫書與修改建議，聚焦品牌行銷人員的「收集 → 查核 → 觀測 → 建議 → 再次觀測」流程。已提供公開網頁收集、附來源與時間的品牌知識資料表、固定 80 題情境題庫、人工品牌觀測及內容改善建議；競爭分析維持「目前競品、替代競品、引用來源」三類。

首頁搜尋或讀取結束後，會依目前成功收集的資料主動整理摘要、內容缺口與優先改善方向，並保留來源連結。模型已連線且允許使用網頁資料時，交由目前選用模型進一步分析；模型未就緒或呼叫失敗時，明確顯示內容比對建議，不將規則結果冒充模型回答；停用網頁資料時停止資料分析。部分抓取失敗不會抹除已取得的資料，建議只適用於實際收集的樣本。

品牌知識的來源內容仍須人工查核；頁面沒有找到某項資訊，不代表品牌未提供該服務。網頁資料、人工查核及外部 AI 回答是不同證據，不能將抓取頁數換算為 AI 推薦率。

### 建立人工 AI 搜尋基準

1. 確認首頁的指定品牌與官方網域，再開啟 AI 品牌觀測，選取固定情境題庫。題庫涵蓋節慶送禮、企業採購、成分食安及預算區間。
2. 將「未指定品牌」問題貼到 ChatGPT 或 Gemini，觀察自然提及及推薦；使用「指定品牌」問題查核品牌資訊。這個提問分類與網站來源的品牌歸屬是兩個獨立維度。
3. 保留題目版本、平台／模型、測試日期、輪次、原始回答及引用網址；重複測試時維持相同問題與條件。模型 API／本地採樣須使用對應來源類型，與平台網頁版人工觀測分開。
4. 逐項標記提及、推薦、引用及資訊正確性；尚未確認保留「未查核」，不要直接標為否。資訊正確性需對照來源，採回答層級人工判定。
5. 查看各組的提及率、推薦率、官網引用率及資訊正確率，核對分子／已查核分母；沒有已查核樣本時不呈現為 0%。保存基準後改善內容，再用相同題庫版本及條件觀測。

尚未包含自動操作 ChatGPT／Gemini 網頁版、完整向量語意 RAG、已完成的 Schema A/B 實驗或已驗證的財務成效。知識整理與內部模型回答改善不代表外部平台推薦率必然提升；計畫書中的成本、回收期及效益假設也不當作系統實績。

## 本機啟動

首次使用時，執行 `powershell -ExecutionPolicy Bypass -File .\setup-agent.ps1 -InstallOnly` 安裝依賴，或直接執行 `start-local.cmd` 讓系統先安裝再啟動。Node.js 24 以上、Ollama 與預設 Qwen3.5 4B 模型都放在 Agent 專案的 `.runtime/`；缺少 Qwen 時會自動下載，已存在的執行檔或模型會略過。執行檔及模型不會進入 Git 或網站部署檔。

也可使用 Agent 內安裝的 Node.js，在專案目錄直接執行：

```powershell
node scripts/dev.mjs
```

開啟 [本機儀表板](http://localhost:4173)。服務只綁定 `127.0.0.1`；修改來源後重新執行指令即可重建。`PORT` 環境變數可調整埠號。

本地來源程式可直接修改、保存與打包；模型下載完成後，本機 AI 生成不需網路或 API key。OpenAI／Gemini 功能需要網路和所選供應商的有效 API key。

## 資料使用

首次開啟為**尚未量測的空白資料集**，搜尋與品牌可見度指標待匯入實際來源後才顯示。舊版 DEMO 資料會移除，不會混入正式指標。品牌名稱與情境範例不代表已取得成效數據。

在「API 與模型」展開「資料匯入、匯出與進階工具」，下載 JSON 範本並填入來源資料。僅匯入具備來源與日期的實際紀錄；可匯入 UTF-8 關鍵字 CSV：

```csv
keyword,cluster,intent,volume,difficulty,clicks,impressions,position,relevance,page
企業送禮,企業採購,商業調查,,,,,,,https://www.idodo.com.tw/
```

- CSV 支援中文及常見 GSC 查詢欄名，匯入關鍵字。
- JSON 包含 `brand`、`keywords`、`daily`、`observations`、`pages`。每日紀錄可帶入 `impressions`、`clicks`、`inquiries`、`aiVisits`、`aioImpressions`；觀測需有日期、平台、問題與判讀標記。
- 未知數字留空或填 `null`，不以零取代。匯入會檢查數字、日期、網址及重複紀錄；單一檔案上限 5 MB。
- 匯入資料、待辦、對話、探索設定、人工基準與模型設定保存在目前瀏覽器的 `localStorage`；本機抓取正文與每日關鍵字快照另存於 `data/web-knowledge.sqlite`。介面清除瀏覽器資料不會刪除 SQLite；一般 JSON 匯出不是完整資料庫備份。
- 保留來源報表的日期與時區，合併前先對齊測量口徑。關鍵字沒有日期歷史，因此排名標示完整匯入期間，不跟日期篩選重新解讀。

## 指定品牌、來源分類與人工基準

在首頁展開「指定品牌與人工基準資料」，依下列步驟建立比較基準：

1. 確認指定品牌名稱與官網網域，填入共同探索主題。
2. 將已核實的來源逐行填為 `名稱 | https://網站 | 類別`，最多 50 個網站。類別僅有「目前競品」（其他月餅／糕餅廠家）、「替代競品」（其他送禮品類）與「引用來源」（部落格、評比或新聞）。
3. 按「保存基準」，以相同主題及頁數或時間收集資料，保留來源日期與實際樣本數。
4. 在來源清單核對「待分類」網站，再選擇三種類別之一；同一網站的頁面會一起更新分類。
5. 按「匯出基準」下載 JSON 備份；之後可用「匯入基準」還原或移到另一個瀏覽器。基準匯入接受匯出的 `baseline` 包裝或基準物件本身，檔案上限 100,000 位元組。

「指定品牌」依官網網域及其子網域辨識，忽略 `www.` 差異；外站即使提到品牌名稱，也屬於「非指定品牌」。其他來源須經人工指定才會進入三類，未確認者保留「待分類」。首頁可篩選指定／非指定品牌，關鍵字頁可查看兩類對應頁數與三類來源摘要；這些都是已收集樣本，沒有推算市場規模或市占率。

人工基準按品牌工作區保存在此瀏覽器；切換官網網域會切換工作區，不會把原品牌資料庫頁面移到新品牌。基準 JSON 保存品牌、主題及分類設定，不包含正文、金鑰或完整資料庫。一般成效報告另附 `sourceBaseline` 供查閱；要還原基準請使用專用「匯入基準」。

## 關鍵字引擎與測量口徑

「關鍵字與 Agent」以實際保存的標題、段落與正文進行比對：**內容涵蓋率 = 提及關鍵字的頁數 ÷ 本次分析頁數**。本機最多分析最近 100 頁、20 個關鍵字；同頁重複出現只計一頁。點選關鍵字可查看相關頁面與來源摘錄。內容涵蓋不是搜尋量、搜尋熱度、排名或市場占有率；搜尋量及排名只顯示已匯入的數值。

本機會在更新分析時寫入台北日期的每日快照，同一天、同一品牌與同一關鍵字更新原紀錄。歷史圖讀取最近 30 天的實際觀測，至少兩個日期才呈現變化，不補造未觀測日期；各日頁面樣本數可能不同。API 為 `POST /api/library/keywords`，詳見 [API.md](API.md)。

Agent 在模型已連線、允許使用網頁資料且頁面或追蹤詞更新時，自動依資料提出建議；首頁收集完成後即可查看，不必先切換分頁。模型尚未就緒時先顯示內容比對建議；使用者也可按「重新分析」或直接提問。草稿保留提供給模型的來源連結。

既有進階引擎仍保留機會分數：正規化搜尋需求 × 35% + 排名機會 × 30% + 低難度 × 20% + 品牌相關性 × 15%。缺少搜尋量、排名、難度或相關性時不計分；規則位於 `src/engine.js`，不可用來預測排名或 AI 推薦。

SEO 的 CTR 用同日期有完整資料的點擊與曝光計算。此產品將 **AIO** 定義為 Google AI Overviews／AI Mode 的連結曝光；GSC 搜尋總曝光已包含該曝光，兩者不可再次相加。**GEO** 是題庫採樣：提及率與推薦率以已標記回答為分母，官網引用率以已查核引用的回答為分母。頁面收錄率只計入有已知收錄狀態的頁面。

## 首頁主題探索與保存

首頁以「探索主題，累積資料」為主要入口，預設主題來自人工基準（初始為月餅、糕餅與糕餅廠家）。選擇「同業品牌」、「相關主題」或兩者，再按「開始探索」。本地 Qwen 規劃搜尋詞預設勾選；模型未連線時使用規則查詢，實際網址及正文仍由網頁工具取得。

- 停止條件可選 **100／150／200 頁**，或 **1／3／5／10／20 分鐘**；初始為 100 頁。每批最多讀取 6 頁，整次最多 200 頁、20 分鐘或 60 批，規劃與讀取共用時間額度。
- 可勾選「同時讀取指定網址」，每行一個、最多 5 個。系統先讀取這些網址，再進行主題搜尋；共用頁數與時間，若指定網址先用完額度，本次就不再搜尋其他網站。
- 「停止探索」會等待目前作業回傳並保存結果，再停止新批次。來源不足、查詢已用完、連續兩批沒有新增頁面、讀取時限或服務限制，都可能提前結束；不會等待時間耗盡才回報。
- 頁數只累計本次成功取得的不同網址，移除 fragment 後去重；搜尋摘要不算已讀取頁面。「本地已保存」僅計入後端確認成功寫入的不同來源，與讀取數分開顯示。

探索期間請保持頁面開啟；這是頁面內的連續作業，不是關閉瀏覽器後仍執行的背景排程。下方儀表板與來源清單可核對實際讀取結果。

指定網址的 `idodo.com.tw`／`www.idodo.com.tw` 使用官網 HTML 爬取，先檢查 `robots.txt`，上限 6 頁、深度 2、總時限 40 秒。其他公開 HTTPS 網站透過固定的 **Jina Reader** 轉換為文字並要求遵守 `robots.txt`；外部遍歷 API 預設 3 頁、可指定 1–12 頁、深度 2，單頁最多 25 秒、總時限 75 秒。只沿實際回傳的同 hostname 連結，不跨子網域，略過私人路徑、查詢參數及明顯非網頁檔案。Reader 內容未直接驗證原始 HTML 的 meta description、H1/H2、FAQ 或 JSON-LD。

外部網址會傳送至 Jina Reader，不傳送模型金鑰、Cookie 或登入資訊；服務可能受網站限制或免費流量限制。抓取功能需要網路，不支援登入、會員、購物車、付款或管理頁面，也不接受私人網路、IP 位址、查詢參數與非預設連接埠。

本機所有成功讀取且成功寫入的頁面都持久保存在 SQLite，包含來源與時間，沒有 12 或 100 頁的總儲存上限，也不會因關閉瀏覽器或重啟而消失。相同品牌工作區、相同 URL 再抓取時更新現有資料。失敗時保留既有頁面並顯示原因；若磁碟寫入失敗，明確標示未保存。

各項上限用途不同：**SQLite 保存全部來源；關鍵字分析最多 100 頁；瀏覽器暫存最多 100 頁；首頁來源清單顯示最近 12 頁；模型每次最多取用 6 頁摘錄**。線上版無法寫入使用者電腦的資料庫，只提供瀏覽器暫存。

在「關鍵字與 Agent」也可輸入「抓取 https://example.com/ 並摘要重點」。單純要求抓取時只收集與保存；明確要求摘要或分析時再呼叫目前選用模型。Agent 的「使用網頁與本地資料庫」（`useWebData`）預設勾選，最多帶入 6 頁來源摘錄。預設由本機 **Qwen3.5 4B** 分析；切換雲端 API 後，任務及選用摘錄會傳至所選供應商。

對話中的來源連結表示本次提供給模型的抓取資料，應點開核對；抓取、摘要與內容建議不會改寫搜尋量、排名、流量、AIO 曝光或 GEO 品牌觀測等量測指標。接口與範例見 [API.md](API.md)。

## 本機模型與 API 設定

預設使用 **本機 Ollama · Qwen3.5 4B · `qwen3.5:4b`**。「API 與模型」可切換本機模型與雲端 API；本機模式固定透過後端連線至 `127.0.0.1:11434`，不接受自訂外部服務位址、不需要 API key，也不會在失敗時自動切換雲端。

「檢查本機模型」會讀取 Ollama 模型清單，分別確認服務連線與所選模型是否已安裝。檢查成功不會生成內容；首次生成載入模型可能較慢。內容提案與品牌觀測皆由統一後端執行，來源標記 `local_api`。雲端部署的 Worker 預設不啟用本機模型。

切換 OpenAI 時，預設使用 `gpt-6.1-sol`、推理 `low`（輕度）。亦可選擇 Gemini；兩家供應商使用獨立金鑰與模型設定。

金鑰設定方式擇一即可：

1. 在「API 與模型」選擇供應商、輸入其 API key 並套用。金鑰只留在目前頁面的記憶體，重新整理即清除，不寫入 `localStorage`、日誌或匯出報告。
2. 複製 `.env.example` 為 `.env`，依下表填入設定，再啟動本機服務。也可由執行環境提供同名變數；環境變數優先於 `.env`，伺服器金鑰優先於介面金鑰。

| 供應商 | 環境設定 | 預設模型／推理 | 同源接口 |
| --- | --- | --- | --- |
| 本機 Ollama | `LOCAL_MODEL_ENABLED=true`、`LOCAL_MODEL` | `qwen3.5:4b` | `/api/local` |
| OpenAI | `OPENAI_API_KEY`、`OPENAI_MODEL`、`OPENAI_REASONING_EFFORT` | `gpt-6.1-sol`／`low` | `/api/openai` |
| Gemini | `GEMINI_API_KEY`、`GEMINI_MODEL` | `gemini-3.8-flash` | `/api/gemini` |

OpenAI 使用 Responses API，設定 `store: false` 與 `reasoning.effort`；Gemini 使用 Google GenerateContent API。請使用 **OpenAI API key**，不要填入 ChatGPT 密碼。本接口依 OpenAI API 帳戶計費，與 ChatGPT 訂閱分開；Gemini 依 Google API 帳戶計費。`.env` 不會包含在打包產物。

模型透過應用程式的抓取與搜尋工具取得來源；一般內容提案與問答採樣中的模型自述網址不能當作已查證引用，也不代表 ChatGPT、Gemini 網頁產品、Perplexity 或 Google AI Overviews 的回答。本機模式將品牌、關鍵字與文字交給本機 Ollama；選用雲端 API 時則送至所選供應商。既有 OpenAI 網路研究 API 保留獨立 `research` 模式，行為見下方。端點與錯誤格式見 [API.md](API.md)。

## 官網遍歷與網路研究

讀取指定網址遇到 `idodo.com.tw`／`www.idodo.com.tw` 時使用原有官網爬取器，`POST /api/crawl` 也保留此接口。它先檢查 `robots.txt`，最多 6 頁、深度 2；單次請求最多 8 秒、總時限 40 秒、HTML 每頁最多 512 KiB。遇到限制或部分頁面失敗會保留已取得內容。此功能不執行頁面 JavaScript，無法代表整站完整掃描或確認 Google 收錄。

選用 OpenAI 研究時，`research` 模式要求真實 `web_search` 工具與 live access，最多等待 90 秒；只有工具完成且回傳可追溯來源才建立研究報告。報告提供來源連結與行內引用，協助查看搜尋意圖、公開品牌內容與改善方向。需要有效 OpenAI API key，並會使用模型與搜尋工具額度。此功能仍未以使用者真實金鑰執行模型或 web_search 測試；mock 通過不代表正式帳戶權限與工具已驗證。

官網與網路研究結果獨立呈現，不改寫已匯入資料或流量 KPI，不產生未測量的搜尋量、SERP 排名、曝光、點擊或 AI 推薦率。

「檢查接口」會使用無認證的 `/api/connectivity` 探測官方端點。401 表示部署環境可連到需要認證的端點，不表示金鑰、模型權限或額度已驗證。供應商請求使用手動轉址，遇到 3xx 即停止；診斷日誌只記錄白名單分類，不記錄金鑰或原始例外。

## OpenClaw 本機接口

在「API 與模型」選擇 OpenClaw，代理預設為 `openclaw/main`。支援內容優化與品牌觀測，來源會標記 `openclaw_api`。首頁抓取及搜尋工具獨立運作，不依賴 OpenClaw。

本機 OpenClaw 安裝在 `C:\Code\Codex\openclaw-local`，屬於選用的進階接口。先執行本專案的 `start-local.cmd` 啟動 Ollama 與網站；需要 OpenClaw 時再執行其 `start-openclaw.cmd`。預設本機模式直接使用 Ollama，不需要額外啟動 Gateway。

OpenClaw 的預設主模型與 `main` 代理已設為 `ollama/qwen3.5:4b`，沒有雲端備援。`setup.mjs` 可重套此設定並保留 Gateway token。若需改用雲端帳戶，可執行 `configure-model.cmd`；`dashboard.cmd` 開啟管理介面。設定後重新啟動 OpenClaw。

網站後端從獨立的 `openclaw-local/state/openclaw.json` 載入 Gateway token，不會傳回前端。此 token 與模型 API key 不同。連線測試只讀取 Gateway 代理清單，不呼叫模型；成功不代表模型帳戶已可生成。

Gateway 綁定 loopback 18789，網站只允許固定此位址且拒絕轉址。本機設定關閉代理工具與週期心跳；只提供內容生成。部署到雲端的 Worker 不啟用本機 OpenClaw 接口。請勿把 state、模型憑證或 token 上傳至原始碼倉庫。


## 多頁搜尋與本地網頁資料庫

執行 `start-local.cmd` 後，可使用首頁主題探索，規劃最多 60 個搜尋詞並逐批讀取（本地模型最多 12 組優先查詢，再補規則查詢）。也可在「關鍵字與 Agent」輸入「搜尋鴻鼎菓子企業禮盒，找 12 個網頁並比較」，執行一次搜尋；此單次工具由 Qwen 最多補充兩組搜尋詞，並非首頁的多批探索。模型未連線時仍可用規則或原始關鍵字搜尋。

未設定 Jina 金鑰時使用 DuckDuckGo 公開搜尋；設定後使用 Jina Search。搜尋到的公開 HTTPS 頁面由 Jina Reader 讀取。若服務要求驗證、限制流量或拒絕存取，會顯示部分失敗並保留已取得的頁面，不繞過限制或捏造內容。每批最多 3 個頁面同時讀取，搜尋與讀取預算上限 75 秒。首頁先獨立規劃（最多 15 秒，且不超過剩餘預算），後續各批不重複規劃；Agent 單次搜尋的規劃也計入該次時間預算。

本機會把抓取內容直接存入 `data/web-knowledge.sqlite`（Node.js 24 的內建 SQLite），包含品牌工作區、網址、標題、正文（每頁最多 24000 字元）、來源時間與搜尋詞。同一工作區的相同網址會更新，不重複建立。資料不會隨瀏覽器關閉而消失，且 `data/` 不會進入 Git 或部署檔案。

每次開啟可重新載入本地資料，關鍵字分析載入最近 100 頁；後續提問會先以問題搜尋資料庫，再把最多 6 頁相關摘錄交給模型。這是文字檢索，尚未使用向量資料庫。首頁來源清單顯示最近 12 頁，瀏覽器暫存最多 100 頁，SQLite 持久保存全部成功寫入的來源，且清除瀏覽器資料不會刪除 SQLite。

線上網站也有搜尋介面，但雲端無法寫入使用者電腦的 SQLite，會明確顯示瀏覽器暫存模式。請使用本機版完成持久保存。模型選擇 API 時，選用的摘錄會傳給該模型供應商。

測試涵蓋同網站遍歷的深度、頁數、時限、私人網址排除、部分失敗保存，以及每日快照的台北日期、品牌隔離、同日更新與真實歷史。外部服務可能拒絕或逾時，介面保留失敗原因；未使用真實付費 Jina key 驗證額度。

## 網頁讀取服務金鑰

外站抓取使用 Jina Reader，可不提供金鑰；線上部署的共用出口可能遇到免費額度限制（HTTP 429）。可在「API 與模型」的「網頁抓取服務」填入自己的 Jina Reader API key，按「套用設定」後重新抓取。此金鑰與 Qwen／OpenAI／Gemini 模型設定分開，僅保留在本次頁面記憶體，重整即清除，不寫入瀏覽器儲存、匯出報告或來源程式。

也可在伺服器環境或本機 `.env` 設定 `JINA_API_KEY`；伺服器金鑰優先於介面金鑰。金鑰只傳送至固定的 Jina Reader／Jina Search 服務，不轉送至品牌官網，也不作為模型 API key 使用。使用自己的金鑰時依該服務帳戶額度處理。本地模型仍預設為 Qwen3.5 4B。

實測：本機公開網頁抓取、AI的烘焙口袋名單：是否同意Cookies 同步與本地 Qwen 引用分析均已成功；線上版未設定讀取服務金鑰時曾回報免費流量限制。尚未使用真實 Jina API key 驗證付費／獨立帳戶額度。
